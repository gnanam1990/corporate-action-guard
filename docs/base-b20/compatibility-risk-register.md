# Compatibility risk register

Every way the Base work could break the working X Layer product, with the specific control
that stops it. Ordered by what would hurt most.

| #   | Risk                                                                             | Why it is plausible                                                                       | Control                                                                                                                                                 | Verified by                                                                                            |
| --- | -------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------ |
| 1   | A B20 reason code is inserted into `BLOCK_REASONS` in the middle of the array    | `orderReasons` sorts by declaration index; an insertion silently reorders existing output | New codes append only; the severity map and explanation map are exhaustive by type                                                                      | Existing reason-ordering tests, plus a test asserting the first 22 codes and their order are unchanged |
| 2   | The X Layer EIP-712 receipt schema changes                                       | Both receipts want the same field names, and "just add a field" is one line               | B20 gets its own versioned typed-data struct and its own vectors. The X Layer vectors are frozen fixtures                                               | `packages/receipts/test`, `contracts/test/GoldenVectors.t.sol` — both must pass byte-identical         |
| 3   | A migration rewrites or backfills existing journal rows                          | A Base projection wants a column the old events lack                                      | Forward-only migrations; the DB trigger rejects `UPDATE`/`DELETE` on journal rows; new columns are nullable or live on new tables                       | `journal.integration.test.ts` plus a migration test that runs against a copy of the current schema     |
| 4   | `evaluatePreflight` gains a B20 branch                                           | Sharing one entry point looks like reuse                                                  | B20 preflight is a separate evaluator. The X Layer function keeps its exact signature and behaviour                                                     | `packages/domain/test/preflight.test.ts` unchanged                                                     |
| 5   | The layering rule is loosened to let a new package import a sibling              | Real dependency pressure between `b20-reader`, `chainlink-reader` and `equity-ledger`     | New packages get explicit layers; shared logic moves _down_ into `domain`, never sideways                                                               | `pnpm arch:check`                                                                                      |
| 6   | `@cag/explainer` gains an import so it can explain B20 evidence                  | The B20 evidence graph is richer and the temptation is real                               | The isolation rule is mechanical and unchanged: explainer may import nothing                                                                            | `pnpm arch:check`                                                                                      |
| 7   | Base config parsing throws at startup for X Layer-only deployments               | Adding required env vars to a shared schema                                               | Every Base variable is optional; Base features are off unless explicitly enabled; an address string alone enables nothing                               | `packages/config/test/load.test.ts` with a Base-free environment                                       |
| 8   | A Base RPC secret reaches the browser bundle                                     | New `NEXT_PUBLIC_` variables for a new UI surface                                         | The existing bundle scan is extended with the Base variable names                                                                                       | `pnpm scan:bundle`, `pnpm scan:secrets`                                                                |
| 9   | Base worker jobs starve X Layer jobs, or steal their leases                      | One worker process, shared lease table                                                    | Distinct partition keys per job family; backfill is rate-limited and never preempts live ingest                                                         | Concurrency tests running both job families                                                            |
| 10  | An X Layer API response shape changes because a shared serializer was "improved" | Money and digest formatting is shared                                                     | Base routes live under `/v1/b20` with their own schemas; the OpenAPI drift test compares against the committed contract                                 | `apps/api/test`, OpenAPI drift test                                                                    |
| 11  | The readiness table stops matching `docs/modules.json`                           | Two module numbering schemes now coexist (X Layer 00–23, B20 00–34)                       | B20 modules are recorded with a `b20-` prefixed id in the same generated source                                                                         | `pnpm docs:check`                                                                                      |
| 12  | A fixture asset appears in a production asset list                               | One registry, two kinds of asset                                                          | Fixtures live in a separate manifest and a separate namespace, and carry `TESTNET FIXTURE — NOT COINBASE STOCK` in metadata, API, logs, evidence and UI | Registry tests asserting a fixture can never reach `VERIFIED` on a production route                    |
| 13  | The provenance check becomes a required CI job and a Base outage blocks merges   | It looks like a correctness gate                                                          | It runs on a schedule alongside the existing live probes, and `check` exits 0 with an explicit `SKIPPED` when a source is unreachable                   | `live-probes.yml`; the skip path is exercised by disabling network access                              |
| 14  | Foundry gas snapshots shift because new contracts were added                     | Shared snapshot file, toolchain-sensitive                                                 | New contracts get their own snapshot entries; the pinned 1.7.1 toolchain stays pinned                                                                   | `pnpm test:contracts` in CI                                                                            |

## Rollback

Each phase merges as one squashed commit on `main`. Because every phase is additive and
feature-flagged off by default, reverting a Base phase is `git revert` of that commit plus a
migration that is forward-only and unused — no X Layer data path depends on any Base table.
